Who can sign Alcove, and how.

Alcove is Cromis's Windows desktop organizer. It can start at sign-in and replaces Explorer's desktop icon view. This policy covers who approves releases, how signing keys are held and which builds we will sign. Update signatures are in use. Windows code signing is still pending.

The current installer is not Authenticode-signed, so Windows SmartScreen may warn when you first run it. Our application for a free certificate through an open-source signing programme was declined because Alcove is too new to meet its established-project requirement. Repository stars and installs are measures of usage for a future application. The Windows signing requirements below apply to future Authenticode-signed builds.

01 Roles A short list

One maintainer holds all three roles.

Alcove is written by one person in their own time. The same maintainer writes the code, reviews the installer and approves releases. The source and build pipeline are public, but there is no independent reviewer or approver.

Signing roles for Alcove releases
RoleWho, and what they may do
AuthorThe maintainer. Writes the code and pushes the version tag that starts a release build.
ReviewerThe maintainer. Checks the built installer against the tag it claims to come from before anything is published.
ApproverThe maintainer. The only person who may approve a signing request or publish a release.

If another person gains signing approval rights, we'll update this page that day. The change will be recorded in the site's git history. Multi-factor authentication is required for every role on the source repository and will be required on the signing service once one is in use.

02 Keys Updates and Windows signing

Where the keys live.

Alcove uses a key to sign updates. A separate Authenticode certificate, once obtained, will identify the publisher to Windows. Private keys are kept out of the repository and may only be used on build machines we control.

Key 1

The update key

A minisign key signs every update artifact. Alcove only accepts updates that verify against the public key in tauri.conf.json. The maintainer holds the private key offline. It has never been in the repository and cannot be regenerated. If it were lost, we couldn't sign further updates that existing installs would accept. A replacement key would not match their stored public key.

Key 2

The Windows signature

Authenticode identifies the publisher in Windows dialogs such as UAC. Alcove is not Authenticode-signed, as noted on the download page. Update signatures do not replace Windows code signing or remove the SmartScreen warning. We'll document the certificate and publisher name here before the first Authenticode-signed build ships.

Version 0.2.4 was the first release built by GitHub Actions from a tagged commit. It includes a build attestation you can verify against the repository and a SHA-256 checksum beside the download. Releases 0.2.3 and older were built manually and have only a checksum, which lets you compare the file with the published download but does not verify how it was built.

03 Scope Alcove releases

Which builds qualify for signing.

Will

Builds from our public repository

We only sign binaries built by our pipeline from a commit in our repository's public history. We don't sign files supplied by others or sign on their behalf.

Won't

Anything that attacks a machine

Signing excludes hacking tools, code designed to exploit vulnerabilities, adware and third-party payloads bundled with the installer.

Won't

Obfuscated or closed components

The policy requires every component we sign to have readable, MIT-licensed source, apart from the platform libraries Windows itself provides.

04 Privacy Data and removal

What Alcove stores and how to remove it.

These behaviours apply to the current build, regardless of its Windows signing status.

Data

Your layout stays on your disk

Alcove works offline and requires no account. It has no telemetry, analytics or crash reporting. Its network use is limited to checking for and downloading updates, and you can inspect that code in the repository. Your layout is stored locally at %APPDATA%\com.alcove.desktop\desktop.json.

Removal

Uninstall through Windows

The installer runs as the current user, needs no admin rights, and uninstalls from Windows' Apps list. Uninstalling also removes the sign-in entry. Ctrl+Shift+F12 restores Explorer's desktop at any time, without uninstalling anything.

05 Reporting Tell us

Report a suspicious build or signature.

If you find an installer we didn't publish, a signature that fails verification or an unofficial download mirror, email hello@cromis.org with what you found and where. We'll help investigate misuse of any certificate bearing our name. Official builds are published only on the releases page.
