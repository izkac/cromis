Make the agent finish the job.

A coding agent will happily tell you it is done. ForgeKit installs the skills that make it prove it: Forge, a workflow that turns a feature request into a tracked change with a gate at every phase, and thorough code review, a review pipeline you invoke on purpose. The gates are mechanical rather than polite: a session cannot reach done while a test is stubbed, a capability is unwired, or acceptance was never actually executed.

01 What it does 3 functions, recorded

A pipeline, not an atmosphere.

Forge never starts on its own. You ask for it by name, and from that point the work has phases, artefacts, and a gate at the end of each one.

1.1

Seven phases, each leaving something behind

A request becomes a tracked change: a proposal, a design, a task list, and a plain-language operator brief that is the thing you actually read. Implementation runs one subagent per task group, test first, with a review at every group boundary. Nothing advances on an assurance; each phase transition is a command that is allowed to refuse.

1.2

It argues against its own ceremony

Most work does not need a pipeline, and the tooling agrees. Triage sends a rename or a question straight through. Even mid-session, a plan that turns out small enough trips an exit ramp and the agent offers to leave Forge before scaffolding any specs. A high-risk change gets no such offer, however small it looks.

1.3

Gates that count, not gates that ask

A capability that gets claimed has to appear in the spine matrix with real runtime behind it. Acceptance is an executed command with a recorded hash, not a paragraph saying it passed. Wiring left for later goes into the deferral registry, where it stays visible. forge integrity-check runs at the close and refuses a session that faked any of it.

02 Good behaviour Compliance record

It sits beside your agent, not in front of it.

ForgeKit is files on your disk and a CLI on your PATH. There is no service in the middle and nothing to sign up for.

  • Your agent, unchanged. Claude Code, Cursor, Codex, GitHub Copilot, Gemini, Windsurf and opencode all read the same skill folder. Pick your harnesses at install; running it again reconciles the difference.
  • Nothing runs unasked. Forge starts when you invoke it. Thorough code review never auto-loads at all: you ask for it by name or it does not happen.
  • The planning engine is yours. Use the OpenSpec CLI if you have it, the built-in specs engine if you do not. Both share a change layout, so switching later moves no files.
  • Counts, never content. Session metrics are harvested afterwards from transcripts your agent already wrote: model names, tool names, phases, timestamps, totals. Prompts, replies, command strings and file contents are never recorded.
  • Nothing is sent anywhere. Metrics land in a file inside your project. No endpoint, no key, no account. Telemetry that cannot run degrades to unavailable and gets out of the way rather than blocking a phase.
  • Uninstall is a delete. forgekit uninstall removes the skill directories. What is left is your repository, exactly as your agent left it.

03 What gets installed Table 1

Five skills, three commands.

ForgeKit register: the skills, and the CLIs that drive them
NameWhat it is
forgeThe workflow skill: triage, phases, gates, integrity, scorecard
thorough-code-reviewA review pipeline over a branch or a diff: signals, carryforward, merge, render
archive-to-adrTurns an archived change into an Architecture Decision Record
git-resolve-adr-conflictSettles the merge conflicts an ADR index collects
plain-languageTakes the jargon out of what the agent writes back to you
forgekitThe installer: pick skills against agents, then list, update, uninstall
forge · reviewThe two day-to-day CLIs, same package

ADRs are optional and stay off until you pick them. Enabling them installs the two ADR skills and scaffolds an index, a decisions file, and the hooks that speak up when a change is archived without one.

04 Licence MIT

MIT. Free, and free to fork.

ForgeKit is the Cromis product that is properly open source: MIT, published on npm, source on GitHub, fork it and go. It is a developer tool, and a developer tool you are not allowed to read is a developer tool you have no reason to trust.

The Forge skill and several of its bundled workflows — brainstorming, TDD, subagent-driven development, verification before completion, systematic debugging — began as Superpowers skills (MIT) and were adapted into a maintained fork. Superpowers is not required at runtime. The planning engines, the ADR skills, the review pipeline and the CLI are ForgeKit's own.
