Development and review skills for coding agents.

ForgeKit is Cromis's toolkit for working with coding agents. Forge takes a feature request through planning, implementation, testing and review, with command-based checks before each phase can advance. Thorough code review is a separate review workflow you invoke by name. Before a session can reach done, the checks require implemented tests, connected capabilities and a recorded acceptance run. If the project needs a test harness, Forge helps build one with your approval. Findings stay in the project after a session ends, and a shared table shows the Forge sessions running across your machine.

01 What it does Four things

Start Forge when the work needs it.

Invoke Forge by name to start a tracked workflow. Each phase produces project records and has checks that must pass before the next phase begins.

1.1

Seven phases with a record of the work

Your request becomes a tracked change: a proposal, a design, a task list, and a plain-language operator brief for you to review. Implementation runs one subagent per task group, test first, with a review at every group boundary. A command checks the requirements for each phase transition and blocks it when they aren't met.

1.2

Small changes can skip the full workflow

Triage routes simple renames and questions straight to the agent. If planning shows that a change is small enough, an exit ramp offers to leave Forge before creating specs. High-risk changes stay in the workflow regardless of size.

1.3

Checks for implementation and test evidence

Each claimed capability must appear in the spine matrix, which maps it to runtime code. Acceptance requires an executed command with a recorded hash. Connections between components left for later go into the deferral registry. At the end, forge integrity-check checks these records and blocks completion if the required evidence is missing or inconsistent.

1.4

Set up acceptance tests for the project

/forge:harness examines the project and proposes how to start it, how to test a path through the running product, and what a fresh checkout needs installed. You approve the proposal before the agent builds the harness, which becomes part of the repository. Once verified and recorded, the harness is reused by later sessions.

Forge records prerequisites such as browsers, drivers and toolchains. It doesn't detect or install those tools. If an acceptance run later fails, Forge points to the prerequisites first so you can check for differences between the agent's environment and your own.

02 Across sessions Session list and findings

Track sessions and keep project findings.

Forge keeps a machine-wide session list and a findings ledger in each project. You can check work in progress and return to findings after the chat has closed.

2.1

View Forge sessions across projects

Forge sessions register themselves, so forge fleet list shows you all of them at once, across projects and across editors, with phase, task count, health and age. watch is the live view. view <session> --transcript 20 tails what an agent is saying. send sends a message to a running session and it arrives on the next turn. Start two sessions in one project and both agents get a warning. You can continue, move one to a worktree, or pause it.

forge fleet report summarises grades, review depth and how often a gate was capped across sessions.

2.2

Keep findings with the project

Out-of-scope bugs, technical debt, tradeoffs and ideas are recorded with a kind, severity and id. Findings can depend on one another, be resolved with a note, or be reopened with a reference to the earlier finding.

Gate waivers go into the project ledger too, so their record remains after the session ends. forge cleanup removes temporary files from finished sessions and keeps the ledgers.

03 Integration and privacy Local files and metrics

Use ForgeKit with your existing agent.

ForgeKit installs local skill files and a CLI on your PATH. It requires no ForgeKit account or intermediary service. Your coding agent and model service have their own account requirements and data policies.

  • Seven supported agents. Claude Code, Cursor, Codex, GitHub Copilot, Gemini, Windsurf and opencode read the same skill folder. Choose your agents during installation. Run the installer again to update those choices.
  • Start workflows by name. Forge starts when you invoke it. Thorough code review also requires an explicit request and never auto-loads.
  • Choose a planning engine. Use the OpenSpec CLI or the built-in specs engine. Both use the same change layout, so you can switch without moving files.
  • Metrics exclude conversation content. ForgeKit reads existing agent transcripts to collect model and tool names, phases, timestamps and totals. Its metrics exclude prompts, replies, command strings and file contents. The agent's original transcripts are separate.
  • Metrics stay in the project. ForgeKit writes metrics to a local project file without sending them to a service. If collection can't run, metrics are marked unavailable and the phase can continue. This doesn't change what your agent sends to its model service.
  • Remove the installed skills. forgekit uninstall removes the skill directories. It leaves your repository and the agent's changes in place.

04 What gets installed The full list

Five skills, three commands.

Skills and command-line tools
NameWhat it is
forgePlans and tracks a change through coding, testing and review
thorough-code-reviewReviews a branch or diff, verifies findings and writes a report
archive-to-adrTurns an archived change into an Architecture Decision Record
git-resolve-adr-conflictResolves merge conflicts in the ADR index
plain-languageGuides the agent to write clear explanations with less jargon
forgekitThe installer: choose skills and agents, then list, update or uninstall
forge · reviewThe two day-to-day CLIs, same package

ADRs are optional and off by default. Enabling them adds the two ADR skills, an index, a decisions file, and hooks that flag changes archived without an ADR.

05 Licence MIT

Free under the MIT licence.

ForgeKit is published on npm with source on GitHub. The MIT licence lets you use, modify and distribute it, including commercially, provided you retain the copyright and licence notices in copies or substantial portions of the software.

The Forge skill and several of its bundled workflows (brainstorming, TDD, subagent-driven development, verification before completion, systematic debugging) began as Superpowers skills under MIT, and we adapted them into a maintained fork. You don't need Superpowers installed to run ForgeKit. The planning engines, the ADR skills, the review pipeline and the CLI are ForgeKit's own work.
